# Quotation extraction test set (synthetic)

130 supplier quotations for the "extraction (fields correct)" target, built to match the
Autonomous Procurement Assistant pipeline: PDF / scan / phone photo / Excel in, nulls left null,
inconsistencies flagged rather than fixed.

**All companies, GSTINs, phone numbers, e-mails and bank details are fictional.** GSTINs have a valid
format and checksum but do not belong to real businesses. Prices are indicative market figures.
The documents were generated by code, so they are a realistic stand-in, NOT real quotations: use them
to build and test the pipeline, and measure the headline number on real quotations.

## Contents
| Folder | What |
|---|---|
| documents/pdf | 50 digital PDFs (5 letterhead styles, one page each) |
| documents/scans | 30 image-only scanned PDFs (no text layer, so OCR is triggered): skew, noise, edge shadow, JPEG artefacts, 8 "poor" |
| documents/photos | 30 phone photos (JPG): perspective, uneven light, shadow, blur, desk background, 8 "poor" |
| documents/excel | 20 .xlsx files in 4 different layouts (merged title rows, shifted header row, optional HSN / lead-time column, extra sheet) |
| requests/rfq_requests.json | the 26 procurement requests; each was quoted by 5 suppliers (like your 4-supplier sample set) |
| ground_truth/Q001.json ... | one correct answer per document (all values, as printed) |
| ground_truth/header_fields.csv, line_items.csv, all_quotations.jsonl | the same ground truth, flat |
| manifest.csv | file -> quotation, format, capture quality, fields missing, inconsistency flag |
| tools/score_extraction.py | field-level scorer (header fields + line fields) |

## What makes it look real
* Same RFQ, different answers: suppliers cover only ~88% of requested lines, rename items, add brands,
  "or equivalent", ISI/BIS tags, occasional typos; some quote per dozen / pack of 10 instead of per piece (`pack_size`).
* Three GST presentations: CGST+SGST or IGST computed (64), "GST extra" not computed (43), rates inclusive of GST (23).
* Fields genuinely absent from the document (stored as null): GSTIN 34, delivery 29, validity 29, phone 22,
  payment terms 18, quotation number 7.
* Extra text that is not a field: terms, disclaimers, bank details, seals, signatures, "amount in words", pen circles on totals.
* 11 documents contain a supplier's own arithmetic error (see `inconsistencies`). Ground truth records the value
  PRINTED, not the corrected one, because your validator should flag, never fix.
* Indian number grouping (1,25,000.00), 5 date formats, several unit spellings (Nos / Pcs / EA ...).

## Ground-truth fields
supplier.{name,gstin,address,phone,email,contact_person}, quotation_number, quotation_date, validity_days / valid_until,
price_basis, items[{description,brand,hsn,quantity,unit,unit_price,amount,requested_line,pack_size}], subtotal,
discount_percent/amount, freight{terms,amount}, tax{mode,cgst,sgst,igst,total}, grand_total (+ computed_grand_total),
payment_terms, delivery_text / delivery_days_min / delivery_days_max, warranty, extra_notes, inconsistencies,
requested_lines_not_quoted, fields_missing_in_source, capture.

I could not see your `schemas/extraction.py`, so these key names are mine. Map them to your contract (rename keys in the
ground truth, or adapt the scorer's HEADER table).

## Scoring
    python tools/score_extraction.py <your_predictions_dir>
A field that is null in the document is correct only if you also return null; inventing a value counts as a miss.

## Honest limits
* No handwriting, stamps over key numbers, multi-language text, or truly crumpled/folded pages.
* Layouts come from 5 PDF templates and 4 Excel layouts, so real quotations will vary more.
* The 70% tune / 30% locked split from your plan is not applied: choose it yourself (keep all 5 quotes of an RFQ on the same side
  so the tuned model never sees the same item mix in the locked set).
